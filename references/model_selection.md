# Flutter Forge Reference - 模型选择策略

本文档提供 controller 在不同角色和阶段选择不同模型层级的推荐策略。模型选择是宿主能力，不是协议要求——宿主可根据实际可用模型自行映射层级。

## 核心原则 [Flexible]

模型选择发生在 controller 调用子代理时。核心思路：**决策质量关键的角色用强模型，执行为主的角色用轻量/标准模型，评估质量关键的角色用强模型**。

不同宿主的模型名称不同，本节只描述层级策略，具体模型名由宿主映射。

## 三级模型策略

| 模型层级 | 适用场景 | 理由 |
|---------|---------|------|
| 轻量模型（cheap/fast） | 机械性任务：1-2 文件修改、规格明确、无需跨模块判断 | 成本低、速度快、上下文消耗少 |
| 标准模型（standard） | 集成性任务：多文件协调、模式匹配、需要理解项目上下文 | 平衡成本与推理质量 |
| 强模型（most capable） | 判断性任务：架构决策、复杂需求分析、品质评估、路由判定 | 需要深度推理、创造性判断、多方案权衡 |

## 角色→模型层级映射

| 角色 | 推荐模型层级 | 降级条件 | 升级条件 |
|------|-------------|---------|---------|
| requirement_analyst | 标准/强 | 简单需求（1-2 个约束，无分支）可用轻量 | PRD 过长或需求冲突多时用强 |
| ui_designer | 标准 | 纯样式调整（颜色/字号/间距）可用轻量 | 涉及布局结构重设计时用强 |
| architecture_designer | 强 | 无例外 | - |
| page_engineer | 轻量/标准 | 轻量任务用轻量 | 多文件协调或调试场景用标准 |
| verify_agent | 标准/强 | 最小验证（轻量任务）用标准 | Rubric 评估和两阶段审查用强 |

## 阶段→模型策略

| 阶段 | 推荐模型层级 | 理由 |
|------|-------------|------|
| S1 需求确认 | 标准/强 | 决策质量关键：需求冻结影响全链路 |
| S2 方案确认 | 标准/强 | 决策质量关键：方案稳定性决定实现效率 |
| S3 拆包冻结 | 强 | 拆包质量影响并行正确性 |
| S4 实现中 | 轻量/标准 | 执行为主：规格明确时用轻量，多文件协调用标准 |
| S5 验证中 | 强 | 评估质量关键：Rubric 评分需要挑剔的判断力 |

## 执行策略映射

| 执行策略 | 推荐模型层级 | 说明 |
|---------|-------------|------|
| ff-（标准） | 按阶段映射 | 各阶段按上表选择 |
| ff-fast（快速） | 全程可用轻量 | 轻量优先，升级后按阶段映射 |
| ff-a（全自动） | 按阶段映射 | 自动决策环节可用标准模型提升质量 |

## 任务复杂度信号

判断当前任务应该使用哪个层级时，参考以下信号：

**→ 轻量模型：**
- 改动 1-2 个文件，规格完整明确
- 纯 UI 文案/颜色/间距调整
- 已定位的单个 bug 修复
- 不涉及状态管理或路由变更

**→ 标准模型：**
- 改动 3+ 个文件，需要理解跨文件关系
- 需要匹配项目已有模式（相似实现检索）
- 中等复杂度 bug 调试
- 需要理解 project_guardrails 约束

**→ 强模型：**
- 架构决策（状态管理选型、模块拆分）
- 复杂需求分析（PRD 冲突、多解并存）
- Rubric 品质评估（需要挑剔的判断力）
- 路由判定不确定时的二次判定

## 成本优化建议

1. **前置阶段（S1/S2）投入强模型**：决策错误的修复成本远高于模型成本
2. **S4 实现阶段使用轻量/标准模型**：规格明确后，执行是机械性工作
3. **S5 验证阶段投入强模型**：评估质量直接决定迭代方向和最终品质
4. **ff-fast 未升级路径全程用轻量模型**：快速路径的核心价值就是效率

## 宿主适配

不同宿主的模型层级对应不同具体模型。以下为示例映射（随时间可能变化）：

| 层级 | Claude Code 示例 | Codex 示例 | Cursor 示例 |
|------|-----------------|-----------|-------------|
| 轻量 | Haiku / Sonnet | gpt-4o-mini | 由 Cursor 自动选择 |
| 标准 | Sonnet | gpt-4o | 由 Cursor 自动选择 |
| 强 | Opus | o1/o3 | 由 Cursor 自动选择 |

> 以上为示例，具体模型名以各宿主当前可用模型为准。controller 只传递层级建议，宿主决定实际映射。

## 与 controller.py 的集成

`scripts/controller.py generate-agent-prompt` 可在输出 JSON 中新增 `model_tier` 字段：

```json
{
  "agent_prompt": "...",
  "context": "...",
  "model_tier": "standard"
}
```

宿主消费 `model_tier` 字段时，映射为实际模型名；不消费时忽略，不影响协议。
