# Flutter Forge Reference - Quality Gates

这个文件定义主控下的统一验证链。验证不再只是页面工程师的附属动作，而是阶段收口的一部分。

## 验证层级

### 轻量任务

只做最小验证：

- 改动文件是否自洽
- 是否存在明显语法、类型或 import 错误
- 是否符合当前局部约束

### 中等任务

做必要验证：

- 相似实现是否保持一致
- 关键文件改动是否对齐当前模式
- 是否出现明显结构越界

### 架构级任务 / 完整流程 / 大任务

做完整验证：

- 需求边界是否被正确保留
- 结构决策是否被正确落地
- 实现是否遵守冻结约束
- 必要的质量门是否已覆盖

## 分阶段质量门

### after_S1_requirement

- 页面目标是否明确
- 关键状态是否覆盖
- 待确认项是否列出
- 是否已经允许进入 `S2`

### after_S2_solution

- UI 或架构结论是否足够支撑实现
- 组件边界或模块边界是否明确
- 是否还有阻断实现的缺口

### after_S3_package_freeze

- 工作包是否完整
- write scope 是否清晰
- 是否仍有共享文件 owner 未定

### after_S4_implementation

- 改动是否仍在授权范围内
- 是否遵守规则卡和冻结约束
- 是否补上必要空态、错误态、加载态

### after_S5_verification

- 是否执行了对应强度的验证
- 是否还有未关闭的高风险问题
- 是否可以进入 `S6 完成`

## 谁负责什么

- `controller`：决定当前阶段需要什么强度的验证
- `impl-agent`：完成实现层自检
- `verify-agent`：在需要时承担统一验证

## 不要做的事

- 不要把验证理解成”代码写完顺手看看”
- 不要让并行实现绕过统一验证
- 不要在结构未冻结前就做最终验证

## 验证失败回退

验证不通过时，按以下规则回退：

| 失败类型 | 回退阶段 | 说明 |
|----------|---------|------|
| 需求边界被突破 | S1 | 回到需求确认，重新冻结边界 |
| UI/架构结论未落地 | S2 | 回到方案确认，重新对齐 |
| 工作包越界或共享约束被破坏 | S3 | 回到拆包冻结，重新拆分或调整 write scope |
| 实现偏离冻结约束 | S4 | 在当前阶段修复后重新验证，不需要回退阶段 |
| 质量门未通过（lint/test/build） | S4 | 修复后重新验证 |

回退原则：

- 回退到对应阶段后，从该阶段的日志重新输出
- 不跳过回退阶段的门禁检查
- 回退次数不设硬上限，但同一问题回退 3 次以上应升级为架构级任务重新评估方案
