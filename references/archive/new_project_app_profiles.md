# Flutter Forge Reference - New Project App Profiles

新项目从 0 到 1 时，需要先判断第一版目标，再决定工程定型强度。

这些 profile 服务的是：

- `C2 工程定型`
- `C3 首批范围冻结`

不是独立主模式。

## 三种 Profile

### mvp

适合：

- 1-3 天内验证想法
- 页面数量少
- 需求可能频繁变化

### business

适合：

- 标准业务应用
- 有登录、列表、详情、表单、接口接入
- 预计持续多个迭代

### team

适合：

- 多人长期维护
- 需要稳定规则卡
- 需要严格工程约束

## Profile 选择规则

如果用户明确指定，按用户指定。

如果用户没有指定：

- 快速 demo / 原型 / 先跑起来 → `mvp`
- 标准业务应用 → `business`
- 团队长期维护 / 规范优先 → `team`
- 无法判断 → 默认 `business`

## 推荐输出格式

```text
[f-forge] 模式：新项目共创
- 升级原因：当前进入工程定型，需要先冻结第一版工程方向
[f-forge] 阶段：C2 工程定型
[f-forge] 架构设计师：
- 新项目 profile：business
- 选择理由：包含登录、列表、详情和接口接入，预计不是一次性 demo
- 当前重点：目录结构、状态管理、路由、网络层、错误处理、页面模板
```

## 五个最小问题

进入 `C2` 时，最多先问 5 个问题：

1. 第一版更接近 `mvp`、`business` 还是 `team`
2. 状态管理偏好是什么
3. 路由方案偏好是什么
4. 是否需要接口层和登录态
5. 是否需要从第一版启用测试、i18n 或 a11y

如果用户没有回答，不要卡死。按 profile 默认值生成工程定型草案，并把低置信度项列为待确认。
