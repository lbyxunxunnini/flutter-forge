# Flutter Forge Reference - Memory Protocol

这个文件定义 Flutter Forge 的记忆读写协议，避免 memory 目录只停留在“有模板，没有时机”。

## 核心原则

skill 仓库内的 `memory/` 目录应视为：

- 内置模板
- 示例规则卡
- 默认画像

真实用户记忆不应默认写回 skill 仓库目录。

默认真实存储目录建议为：

- `${FLUTTER_FORGE_HOME:-~/.flutter-forge}`

也就是说：

- 仓库内 `memory/` = seed / example
- 仓库外 `~/.flutter-forge/` = persisted user state

## 记忆分层

### 1. 跨项目长期记忆

文件：

- `${FLUTTER_FORGE_HOME:-~/.flutter-forge}/global_preferences.yaml`

只存：

- 页面拆分偏好
- 私有组件命名偏好
- 复用倾向
- 业务优先 / 可维护性优先这类稳定偏好

绝不存：

- 某个项目的目录结构
- 某个项目的命名规范
- 某个项目的状态管理模式
- 某次任务的临时业务规则

### 2. 项目级长期记忆

文件：

- `${FLUTTER_FORGE_HOME:-~/.flutter-forge}/projects/<project_name>.rule_card.yaml`

只存该项目的：

- 目录结构
- 模块边界
- 命名规则
- 状态管理主模式
- 组件边界
- API 接入主模式
- 复用知识

### 3. 规则画像 / 模板候选

文件：

- `memory/profiles/*.yaml`

作用：

- 给新项目提供可选初始模板
- 不代表某个真实项目本身
- 用来沉淀跨多个项目抽象出来的常见组织方式

适合存：

- feature + riverpod 画像
- module + bloc 画像
- 常见路由 / 主题 / DI 组合方式

### 4. 短期任务记忆

模板：

- 仓库模板：`memory/runtime/current_task.template.yaml`
- 真实运行时：`${FLUTTER_FORGE_HOME:-~/.flutter-forge}/runtime/current_task.yaml`

适合存：

- 当前任务临时业务规则
- 当前任务字段特例
- 当前任务接口兼容说明
- 当前任务未决风险点

默认：

- 不跨任务持久化
- 不自动提升为长期记忆

## 读取时机

### 任务开始时

1. 先判断是否存在项目级规则卡
2. 如果存在，先读项目规则卡
3. 再读跨项目长期偏好
4. 只有任务进入执行期且需要跟踪临时规则时，才创建或加载当前任务记忆

### 老项目首次接入时

1. 先读 `global_preferences.yaml`
2. 若不存在当前项目规则卡，则扫描项目
3. 扫描后生成新的项目规则卡

### 新项目启动时

1. 读 `global_preferences.yaml`
2. 扫描当前项目已有结构和依赖
3. 读取外部 `projects/*.rule_card.yaml` 和仓库内 / 外部 `profiles/*.yaml` 作为候选来源
4. 由用户选择：
   - 复制已有项目规则卡作为初始模板
   - 使用当前项目扫描结果
   - 使用通用 Flutter 规则 + 全局偏好
5. 最终生成该项目自己的规则卡并逐步补全

## 写入时机

### 写 `global_preferences.yaml`

只有在以下情况才写：

- 用户明确表达稳定个人偏好
- 多个任务中重复出现相同个人习惯
- 该偏好不依赖某个具体项目

### 写 `projects/*.rule_card.yaml`

在以下情况写入或更新：

1. 老项目首次扫描完成后
2. 项目规则被用户纠正后
3. 新任务中发现更稳定的项目主流模式后
4. 明确识别出新的共享组件边界、命名主流或状态管理主模式后

### 写 `memory/profiles/*.yaml`

只有在以下情况才考虑更新或新增：

1. 多个项目重复出现稳定的规则组合
2. 这些规则组合不再依赖单个项目细节
3. 用户明确接受将其作为可复用初始模板

### 写短期任务记忆

只在以下情况使用：

- 当前任务业务规则多且易丢
- 当前任务存在字段特例
- 当前任务 API 兼容逻辑复杂

任务结束后：

- 默认不持久保留
- 只有确认其已经上升为项目规则时，才写回项目规则卡

## 更新策略

skill 升级时：

1. 不应清空外部记忆目录
2. 不应覆盖已有项目规则卡
3. 若模板新增字段，应采用“补缺不覆盖”的迁移方式
4. 若需要迁移结构，优先保留旧文件并生成备份

## 提升规则

短期记忆只有在满足以下条件时，才能提升到项目级长期记忆：

1. 不再是当前任务特例
2. 会影响未来同类页面的实现
3. 能在项目现有代码中找到复用或重复证据
4. 用户没有反对

## 隔离规则

- 不允许把项目 A 的目录结构、命名规范、状态模式直接复制到项目 B
- 跨项目只迁移 `global_preferences.yaml` 中的稳定个人偏好
- 项目规则卡文件名必须显式区分项目
- `memory/profiles/*.yaml` 只能作为候选起点，不能跳过当前项目扫描直接强行落地
