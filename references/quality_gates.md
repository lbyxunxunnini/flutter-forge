# Flutter Forge Reference - Quality Gates

这个文件定义主控下的统一验证链。验证不再只是页面工程师的附属动作，而是阶段收口的一部分。

## 验证层级

### 轻量任务

只做最小验证：

- 改动文件是否自洽
- 是否存在明显语法、类型或 import 错误
- 是否符合当前局部约束

### 中等任务

做必要验证：

- 相似实现是否保持一致
- 关键文件改动是否对齐当前模式
- 是否出现明显结构越界

### 架构级任务 / 完整流程 / 大任务

做完整验证：

- 需求边界是否被正确保留
- 结构决策是否被正确落地
- 实现是否遵守冻结约束
- 必要的质量门是否已覆盖

## 分阶段质量门

### after_S1_requirement

- 页面目标是否明确
- 关键状态是否覆盖
- 待确认项是否列出
- 是否已经允许进入 `S2`

### after_S2_solution

- UI 或架构结论是否足够支撑实现
- 组件边界或模块边界是否明确
- 是否还有阻断实现的缺口

### after_S3_package_freeze

- 工作包是否完整
- write scope 是否清晰
- 是否仍有共享文件 owner 未定

### after_S4_implementation

- 改动是否仍在授权范围内
- 是否遵守规则卡和冻结约束
- 是否补上必要空态、错误态、加载态

### after_S5_verification

- 是否执行了对应强度的验证
- 是否还有未关闭的高风险问题
- 是否可以进入 `S6 完成`

## 谁负责什么

- `controller`：决定当前阶段需要什么强度的验证
- `impl-agent`：完成实现层自检
- `verify-agent`：在需要时承担统一验证

## 不要做的事

- 不要把验证理解成“代码写完顺手看看”
- 不要让并行实现绕过统一验证
- 不要在结构未冻结前就做最终验证
